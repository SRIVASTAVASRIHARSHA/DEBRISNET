Day 1 Project scaffolding + TLE data pipeline Theme: Make real data flow ▾
  • Setup project repo: Create GitHub repo "debrisnet". Init with README, .gitignore (Python + Node). Use Google IDX or Colab for backend dev.
  • Backend skeleton: FastAPI app with a single /health endpoint. Folder structure: /backend (FastAPI), /frontend (React), /data, /scripts.
  • TLE ingestion script: Fetch live TLE data from CelesTrak public API (https://celestrak.org/SOCRATES/) — no API key needed. Pull the "active satellites" catalog and the "debris" catalog separately. Store as .txt files in /data.
  • Parse TLE into structured JSON: Use python-sgp4 library. For each TLE, extract: NORAD ID, name, epoch, inclination, eccentricity, RAAN, mean motion. Save as JSON array.
  • FastAPI endpoint /api/satellites: Returns list of all parsed satellites with basic metadata. Test with curl.
  • Vibe-code prompt: "Build a FastAPI endpoint that fetches TLE data from CelesTrak, parses it with python-sgp4 into a JSON array of satellite objects, and returns paginated results."
End of Day 1 deliverable: FastAPI running locally, /api/satellites returns real TLE data for 500+ objects as JSON. You can see actual Starlink, debris, ISS data in your terminal.

Day 2 Orbital propagation + conjunction detection Theme: The physics engine ▾
  • SGP4 propagation engine: For any satellite NORAD ID, propagate its position forward in 1-minute steps for 72 hours. Output: array of (timestamp, x, y, z) in ECI coordinates. Use python-sgp4's `propagate()` function.
  • Convert ECI to lat/lon/alt: Use pymap3d or manual conversion to get geodetic coordinates from ECI. This gives you the ground track.
  • Conjunction detection: For a given "primary" satellite, compute its position at each timestep. For ALL other objects, do the same. Calculate 3D distance at each timestep. Flag any pair where distance drops below threshold (e.g. 10km). This is the close approach detection.
  • FastAPI endpoint /api/conjunctions/{norad_id}: Takes a satellite NORAD ID, runs conjunction analysis against the top 200 debris objects, returns list of close approach events with timestamps, miss distances, and secondary object names.
  • Optimize with NumPy: Vectorize the distance calculations — naive loop is too slow. Use numpy broadcasting to compute all pairwise distances at once.
End of Day 2 deliverable: POST /api/conjunctions/25544 (ISS NORAD ID) returns real conjunction events in JSON. You should see multiple close approaches — this is the moment it becomes real.

Day 3 LLM risk narrative engine Theme: Make the machine speak ▾
  • Risk scoring function: Given a conjunction event (miss distance, combined object sizes, time to event), compute a risk score 0-100. Use a simple formula: risk = 100 * exp(-miss_distance/1000) * (1 + urgency_factor). Tune the constants.
  • Gemini / Claude API integration: Set up Gemini 1.5 Flash (free tier via Google AI Studio) as the LLM backend. Install google-generativeai SDK.
  • Structured prompt builder: Takes conjunction data JSON → builds a structured prompt that includes: satellite names, NORAD IDs, miss distance (km), time to closest approach, relative velocity, risk score. Asks LLM to produce: summary, severity level (LOW/MEDIUM/HIGH/CRITICAL), recommended action, confidence statement.
  • FastAPI endpoint /api/risk-report/{norad_id}: Orchestrates everything — fetch TLE, propagate, find conjunctions, score, call LLM, return structured report JSON with llm_narrative field.
  • Test with ISS: Generate a full risk report for the ISS. Read the narrative. If it sounds like a real mission briefing, you're done for the day.
End of Day 3 deliverable: Full pipeline works end-to-end in the backend. One API call returns: list of conjunction events + LLM narrative + risk score. Paste the output into a tweet — it'll look incredible.

Day 5 3D orbital visualization Theme: The wow factor ▾
  • Three.js orbital globe: Render a 3D Earth sphere using Three.js. Use a free NASA Blue Marble texture (public domain). Add orbit controls for mouse drag rotation and zoom.
  • Plot orbital track: For the selected satellite, plot its 72-hour ground track as a glowing line on the globe. Use the geodetic coordinates from Day 2.
  • Plot conjunction objects: For each close approach object, draw its orbital path in a different color. Where paths come within range, add a pulsing warning sphere at the conjunction point.
  • FastAPI endpoint /api/orbit-data/{norad_id}: Returns array of lat/lon/alt points for 72-hour propagation, formatted for Three.js (converted to 3D cartesian on globe surface).
  • Color coding: Primary satellite = blue. Debris objects = gray. Conjunction warning zones = red pulsing sphere. Risk level drives sphere size.
  • Vibe prompt for Three.js: "Build a Three.js component that renders a 3D Earth with a NASA Blue Marble texture, plots satellite orbital tracks as glowing lines, and shows pulsing red warning spheres at conjunction points."

Master agent context prompt
You are an expert full-stack developer and aerospace software engineer helping me build DebrisNet — a satellite collision risk intelligence platform. PROJECT OVERVIEW DebrisNet is a web application that: 1. Ingests live Two-Line Element (TLE) orbital data from CelesTrak for 27,000+ tracked space objects 2. Scores each conjunction event with a 0-100 risk score based on miss distance, relative velocity, and object characteristics 5. Generates natural language risk reports using an LLM (Gemini 1.5 Flash / Claude API) that reads like a real mission controller briefing 6. Renders a 3D interactive Earth globe (Three.js) showing orbital tracks and pulsing warning spheres at conjunction points KEY TECHNICAL FACTS - Backend: Python 3.11, FastAPI, uvicorn - Orbital mechanics: python-sgp4 library (SGP4/SDP4 model), pymap3d for coordinate conversion - Data source: CelesTrak public API at https://celestrak.org/SOCRATES/ — no authentication required - LLM: Google Gemini 1.5 Flash via google-generativeai SDK (or Anthropic Claude via anthropic SDK) - Frontend: React 18 + Vite, Three.js for 3D globe, Recharts for charts, Tailwind CSS - Deployment: Backend on Railway.app (free tier), Frontend on Vercel (free tier) - Coordinate systems: TLE uses ECI (Earth-Centered Inertial). Google Antigravity (IDX) workflow
Project IDX is Google's browser-based IDE — it can run a full FastAPI + React stack with no local setup. Use it as your primary dev environment until Day 6 deployment.
  • Go to idx.dev → New workspace → Python template
  • Paste the master prompt into Gemini (the built-in AI in IDX)
  • Use the terminal inside IDX to pip install and run uvicorn
  • IDX gives you a public preview URL automatically — use this to test your API from anywhere
  • For frontend, open a second terminal and run the React dev server
Colab workflow (alternative for heavy computation)
  • Use Colab for testing the SGP4 propagation and conjunction engine in isolation
  • Run !pip install sgp4 pymap3d in the first cell
  • Colab T4 GPU speeds up NumPy matrix operations — useful for large constellation analysis
  • Use ngrok in Colab to expose your FastAPI as a public URL for testing with the React frontend
